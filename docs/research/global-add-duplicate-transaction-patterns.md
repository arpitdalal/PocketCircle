# Global Add and Duplicate Transaction patterns

Research date: 2026-08-21. Sources are first-party product documentation.

## PocketCircle boundary

- A Transaction belongs to exactly one Circle. Currency, Categories, and Paid By options are Circle-scoped; an Archived Circle is readable but not writable. See the [domain glossary](../../CONTEXT.md).
- Circle context is route-derived; PocketCircle has no remembered current or last-viewed Circle, no global Ledger, and no cross-Circle Transaction route. Forms are URL-owned non-object state, permissions resolve reactively, and unavailable objects use non-enumerating fallback copy. See [ADRs 0016](../adr/0016-notion-style-canonical-app-urls.md), [0017](../adr/0017-react-router-framework-mode-spa.md), and [0022](../adr/0022-circle-scoped-mobile-bottom-navigation.md).
- Transaction forms share one TanStack Form model. ADR 0030's Activation Checklist currently continues through Circle-scoped forms and rejects a global form; this effort must reconcile that clause rather than create two form contracts. See [ADRs 0020](../adr/0020-tanstack-form-for-shared-web-native-forms.md) and [0030](../adr/0030-skippable-monotonic-user-activation-checklist.md).
- [Issue 288](https://github.com/arpitdalal/PocketCircle/issues/288) fixes the remaining product envelope: Home has one persistent Add transaction action; a bare global page selects no Circle; Duplicate is an unlinked prefill from Transaction Detail; creation opens the new Transaction Detail while retaining the originating return path.

## Patterns that fit PocketCircle

1. **Global trigger, explicit destination.** YNAB, Monarch, and Splitwise separate where entry starts from the destination stored on the Transaction. PocketCircle should likewise expose one Home action and require Circle selection in the form. Unlike those products, a bare PocketCircle route must not infer Personal Circle, suggest recents, or remember the last Circle.
2. **Context may preselect, never become hidden state.** Monarch and Splitwise support contextual preselection plus global destination choice. PocketCircle can keep its Circle-scoped route and preselect that route's Circle while keeping Type and Circle URL-owned.
3. **Duplicate is “new from this,” not recurrence or linkage.** Lunch Money's detail action and review-before-create model fits best. Copy the portable source fields into an unsaved form, default Transaction Date to today, and store no source ID or lineage. YNAB and Actual's immediate clone is a poor fit because it can commit a stale date or invalid Circle-scoped values before review.
4. **Destination changes must revalidate scoped data.** YNAB exposes account movement separately, while Actual permits account changes as an explicit edit. PocketCircle is stricter for good domain reasons: preserve Type, Title, Note, and Transaction Date; after confirmation clear Amount because Currency may differ, plus Categories and Paid By because their IDs belong to the old Circle. Inline-created Categories remain there.
5. **Historical source does not imply writable destination.** YNAB and Actual retain closed-account history but require reopening for active use; Lunch Money limits writes by account capability. PocketCircle can therefore allow any visible active or Archived source Transaction to seed Duplicate while listing only active, Setup-complete, writable Circles as destinations. An Archived source Circle yields no selected destination.
6. **Live invalidation follows PocketCircle's reactive contract.** The reviewed products document static eligibility, not mid-form permission revocation. ADR 0017 already supplies the stronger rule: re-resolve source and destination reactively. If either becomes unavailable, keep the ordinary global form usable, clear invalid state, and explain the reset with the generic unavailable toast without revealing whether access or existence changed.
7. **Post-create routing should follow the created object.** Register products generally reveal the new row in place; Splitwise historically retained context and confirmed off-screen creation. PocketCircle has no global register, so forcing either pattern would violate ADR 0031. Opening canonical Transaction Detail is the coherent equivalent, provided the original return path is retained and Cancel returns directly.

## Conclusion

Adopt YNAB/Monarch's global-trigger-plus-explicit-destination pattern and Lunch Money's detail-originated, reviewable duplicate; preserve PocketCircle's URL ownership, Circle-local resets, reactive invalidation, unlinked copy semantics, and canonical post-create detail route.
