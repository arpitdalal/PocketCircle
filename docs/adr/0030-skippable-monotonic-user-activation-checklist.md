# User activation is a skippable, monotonic User-level checklist

PocketCircle continues **Onboarding** after the gated profile confirmation with one non-blocking **Activation Checklist** on the **Personal Circle** Dashboard. The checklist has four independent milestones: record a first Personal-Circle **Transaction**, create a Personal-Circle **Category**, create a regular **Circle**, and have another active **Member** join a regular Circle through the User's **Invitation**. Items are never route gates and may be completed in any order. The first incomplete item receives visual emphasis, but every incomplete item remains actionable.

The checklist is User-level rather than split between Personal- and regular-Circle guides. Personal-Circle work proves the solo value loop without false completion from the starter Categories seeded by **Circle Setup**. The regular-Circle milestones then teach collaboration. “Join a shared Circle” is deliberately excluded: PocketCircle Circles are private and undiscoverable, so a User cannot perform that action without an external Invitation. When one arrives, its email and in-app notification provide contextual join onboarding instead.

Completion is monotonic and stored as explicit per-User milestone timestamps. Current entity state is not the source of truth after initialization: archiving a Category, deleting an empty Circle, or a joined Member later leaving must not resurrect Onboarding. A pending Invitation is an intermediate display state only; the collaboration milestone completes when another active Member joins after accepting the User's Invitation. It may complete in any regular Circle the User invited them to and is not bound to a fragile “first Circle” identifier. Existing Users initialize from durable evidence already present at rollout; evidence that no longer exists cannot be inferred and therefore remains incomplete.

The User may choose **Skip onboarding** at any time. Dismissal is persisted independently from milestones, hides the checklist permanently, and does not fabricate completion. Completing all four milestones also hides it. The existing feature-action analytics remain authoritative for Category, Transaction, and Circle creation; the checklist adds only coarse `activation_checklist_skipped` (completed-item count only) and `activation_checklist_completed` events. No Circle, Member, Category, Transaction, email, name, or other identifier is attached.

This decision extends the Onboarding glossary and does not weaken ADR 0023: regular **Circle Setup** remains a mandatory, per-Circle gate. The Activation Checklist begins only after the profile gate and never blocks navigation or writes.
