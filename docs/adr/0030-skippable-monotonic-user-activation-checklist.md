# User activation is a skippable, monotonic User-level checklist

PocketCircle continues **Onboarding** after the gated profile confirmation with one non-blocking **Activation Checklist** on the **Home Summary**. The checklist has four independent milestones: create a first **Transaction** in any eligible **Circle**, manually create a **Category** in any eligible Circle, create a regular Circle, and have another active **Member** join a regular Circle through the User's **Invitation**. Items are never route gates and may be completed in any order. The first incomplete item receives visual emphasis, but every incomplete item remains actionable.

The checklist is User-level rather than split between Personal- and regular-Circle guides. Transaction completion follows **Recorded By**—the User must perform the creation action, regardless of **Paid By**. Category completion follows deliberate User creation; starter Categories seeded by **Circle Setup** never count. The regular-Circle milestones then teach collaboration. “Join a shared Circle” is deliberately excluded: PocketCircle Circles are private and undiscoverable, so a User cannot perform that action without an external Invitation. When one arrives, its email and in-app notification provide contextual join onboarding instead.

Completion is monotonic and stored as explicit per-User milestone timestamps. Current entity state is not the source of truth after initialization: archiving a Transaction or Category, deleting an empty Circle, or a joined Member later leaving must not resurrect Onboarding. A pending Invitation is an intermediate display state only; the collaboration milestone completes when another active Member joins after accepting the User's Invitation. It may complete in any regular Circle the User invited them to and is not bound to a fragile “first Circle” identifier.

The rollout preserves every existing milestone. Existing Personal-Circle Transaction and Category evidence remains valid under the broader rule. Historical regular-Circle Transactions and Categories are not credited retroactively: old Category rows cannot reliably distinguish manual creation from Setup seeding, and rollout must not fabricate completion. New successful creation paths record the broader milestones explicitly; every future Category writer must distinguish manual creation from Setup seeding.

The User may choose **Skip onboarding** at any time. Dismissal is persisted independently from milestones, hides the checklist permanently, and does not fabricate completion. Completing all four milestones also hides it. The existing feature-action analytics remain authoritative for Category, Transaction, and Circle creation; the checklist adds only coarse `activation_checklist_skipped` (completed-item count only) and `activation_checklist_completed` events. No Circle, Member, Category, Transaction, email, name, or other identifier is attached.

The Transaction actions open Global Add at `/transactions/new` with the selected Type, no Circle preselected, and the exact Home Summary URL as `returnTo`. The Category action keeps its eligible-Circle picker and continues through the existing Circle-scoped Category form. No global Category form is introduced. When no eligible Circle exists, the create-or-finish-setup guidance remains.

This decision extends the Onboarding glossary and does not weaken ADR 0023: regular **Circle Setup** remains a mandatory, per-Circle gate. The Activation Checklist begins only after the profile gate and never blocks navigation or writes.
